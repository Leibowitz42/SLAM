# 椅子遮挡导致对极几何约束失效 - 问题与解决方案总结

## 📋 问题描述

**现象**：当椅子被人遮挡时，对极几何约束失效，无法正确判定椅子是否为动态物体。

## 🔍 根本原因

### 问题1：Instance ID 不稳定

```
时间线：
帧 t   → 椅子检测为 ID=1 ✅
帧 t+1 → 椅子被人遮挡，YOLO检测不到 ❌
帧 t+2 → 人走开，椅子重新可见，但被分配新ID=3 ⚠️
```

**为什么会这样？**
- YOLO 每帧独立运行，没有跨帧的物体跟踪
- 检测顺序可能改变（先检测到的物体获得较小的ID）
- 遮挡导致物体暂时消失，重新出现时获得新ID

**导致的问题**：
```cpp
// 当前代码中的逻辑
mMoveConfirmCnt[id]++;  // ❌ ID从1变成3，计数器被重置！
```

### 问题2：数据关联失败

**当前的判定流程**：
1. 按 Instance ID 分组特征点
2. 对每个 ID 调用 `CheckInstanceDynamic()`
3. 累积动态性计数 `mMoveConfirmCnt[id]`
4. 达到阈值（5帧）后删除该ID的所有点

**失败场景**：
```
帧1-3: ID=1, mMoveConfirmCnt[1] = 3
帧4:   遮挡，ID消失
帧5:   重新可见，ID=3, mMoveConfirmCnt[3] = 0  ← 历史信息丢失！
```

### 问题3：MapPoint 被错误删除

遮挡期间：
- MapPoint 失去跟踪
- 可能被标记为 outlier 或 bad
- 重新可见时创建新的 MapPoint
- 无法建立与历史观测的对极约束

## ✅ 解决方案：基于 MapPoint 的语义跟踪

### 核心思想

**从"跟踪 Instance ID"改为"跟踪 MapPoint 的语义属性"**

### 实现步骤

#### 步骤1：在 MapPoint 中添加语义标签

**文件**：`include/MapPoint.h`

```cpp
class MapPoint {
public:
    // 语义类别（创建时确定，不会改变）
    // 0 = 静态背景（墙、地板、桌子等）
    // 1-249 = 半动态物体（椅子、书本等）
    // 255 = 绝对动态物体（人、车等）
    uchar mSemanticLabel;
    
    // 动态性投票计数器（跨帧累积）
    int mDynamicVotes;
    
    // 最后观测到的 Instance ID（调试用）
    uchar mLastSeenInstanceID;
};
```

#### 步骤2：MapPoint 创建时初始化语义标签

**文件**：`src/MapPoint.cc`

```cpp
MapPoint::MapPoint(const Eigen::Vector3f &Pos, Map* pMap, Frame* pFrame, const int &idxF) {
    // ... 其他初始化代码 ...
    
    // 从 Frame 的语义掩码中提取该特征点的语义类别
    mSemanticLabel = 0;
    mDynamicVotes = 0;
    mLastSeenInstanceID = 0;
    
    if(!pFrame->mInstanceMap.empty()) {
        int u = cvRound(pFrame->mvKeys[idxF].pt.x);
        int v = cvRound(pFrame->mvKeys[idxF].pt.y);
        
        if(边界检查) {
            mSemanticLabel = pFrame->mInstanceMap.at<uchar>(v, u);
            mLastSeenInstanceID = mSemanticLabel;
        }
    }
}
```

#### 步骤3：修改动态性检查逻辑（建议实现）

**改进前**（基于 Instance ID）：
```cpp
// ❌ 问题：ID 变化导致计数器重置
for(auto const& [id, featureIndices] : instanceFeatureMapping) {
    bool isDynamic = CheckInstanceDynamic(mCurrentFrame, id);
    if(isDynamic) {
        mMoveConfirmCnt[id]++;  // ID 不稳定
    }
}
```

**改进后**（基于 MapPoint）：
```cpp
// ✅ 解决方案：在 MapPoint 中累积投票
for(int i=0; i<mCurrentFrame.N; i++) {
    MapPoint* pMP = mCurrentFrame.mvpMapPoints[i];
    if(!pMP || pMP->isBad()) continue;
    
    // 只处理半动态物体（椅子等）
    if(pMP->mSemanticLabel > 0 && pMP->mSemanticLabel < 255) {
        
        // 检查该 MapPoint 是否违反对极约束
        bool isDynamic = CheckMapPointDynamic(pMP, mCurrentFrame, i);
        
        if(isDynamic) {
            pMP->mDynamicVotes++;  // ✅ 投票存储在 MapPoint 中
        } else {
            // 衰减机制：如果不动态，减少投票
            pMP->mDynamicVotes = max(0, pMP->mDynamicVotes - 1);
        }
        
        // 达到阈值后删除该 MapPoint
        if(pMP->mDynamicVotes >= 5) {
            mCurrentFrame.mvbOutlier[i] = true;
            pMP->SetBadFlag();
        }
    }
}
```

## 🎯 优势对比

| 特性 | 基于 Instance ID（旧） | 基于 MapPoint（新） |
|------|----------------------|-------------------|
| **抗遮挡** | ❌ ID 变化导致失败 | ✅ 语义标签不变 |
| **历史累积** | ❌ ID 变化时重置 | ✅ 存储在 MapPoint 中 |
| **精细控制** | ❌ 整个 ID 一起删除 | ✅ 单个点独立判定 |
| **数据关联** | ❌ 依赖不稳定的 ID | ✅ 依赖稳定的 MapPoint |

**旧方案（失败）**：

```
帧2: 椅子 ID=1, mMoveConfirmCnt[1]=2
```

```
帧3: MapPoint #123 (语义=椅子), mDynamicVotes=3
帧4: 遮挡，MapPoint #123 暂时不可见

帧6: MapPoint #123, mDynamicVotes=5 → 删除
```

## 💡 核心洞察

> **Instance ID 是易变的，MapPoint 是稳定的。**
> 
> 将语义信息绑定到 MapPoint 上，而不是 Instance ID 上，可以从根本上解决遮挡导致的数据关联问题。

## ⚠️ 注意事项

1. **语义标签的准确性**
   - 依赖 YOLO 的检测质量
   - 边界处的点可能分类错误

2. **MapPoint 的生命周期**
   - 长期存在的 MapPoint 可能累积过多投票
   - 需要考虑时间窗口或投票上限

3. **计算开销**
   - 每个 MapPoint 都需要检查
   - 可以通过语义标签预过滤

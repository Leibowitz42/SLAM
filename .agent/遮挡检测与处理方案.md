# 遮挡检测与处理 - 解决方案

## 🎯 问题描述

**现象**：
- 在15秒左右，ATE暴增到0.05米
- 原因：人走过摄像头，大面积遮挡

**影响**：
- 特征点大量丢失
- 位姿估计不准确
- 关键帧质量下降

---

## 💡 解决方案

### 方案1：遮挡检测与跳过 ⭐ **推荐实现**

**核心思路**：
1. 检测当前帧是否被大面积遮挡
2. 如果遮挡严重，跳过关键帧创建
3. 降低该帧在位姿估计中的权重

**实现步骤**：

#### 1. 添加遮挡检测函数

在 `Tracking.cc` 中添加：

```cpp
bool Tracking::IsFrameOccluded(Frame &frame) {
    // 检查动态区域占比
    if (frame.mInstanceMap.empty()) {
        return false;
    }
    
    int totalPixels = frame.mInstanceMap.rows * frame.mInstanceMap.cols;
    int dynamicPixels = 0;
    
    // 统计动态区域（人体，ID=255）
    for (int v = 0; v < frame.mInstanceMap.rows; v++) {
        for (int u = 0; u < frame.mInstanceMap.cols; u++) {
            uchar id = frame.mInstanceMap.at<uchar>(v, u);
            if (id == 255) {  // 绝对动态物体（人）
                dynamicPixels++;
            }
        }
    }
    
    // 如果动态区域超过30%，认为被严重遮挡
    float occlusionRatio = (float)dynamicPixels / totalPixels;
    
    if (occlusionRatio > 0.3) {
        std::cout << "[Occlusion] Frame heavily occluded: " 
                  << (occlusionRatio * 100) << "%" << std::endl;
        return true;
    }
    
    return false;
}
```

#### 2. 在跟踪中使用遮挡检测

修改 `Tracking::Track()` 函数：

```cpp
// 在创建关键帧之前检查遮挡
if (NeedNewKeyFrame()) {
    // 检查是否被严重遮挡
    if (IsFrameOccluded(mCurrentFrame)) {
        std::cout << "[Tracking] Skip keyframe due to occlusion" << std::endl;
        // 不创建关键帧，继续跟踪
    } else {
        CreateNewKeyFrame();
    }
}
```

#### 3. 降低遮挡帧的权重

在位姿优化中：

```cpp
// 在 PoseOptimization 中
for (int i = 0; i < frame.N; i++) {
    // 检查特征点是否在动态区域
    int u = cvRound(frame.mvKeysUn[i].pt.x);
    int v = cvRound(frame.mvKeysUn[i].pt.y);
    
    if (!frame.mInstanceMap.empty() && 
        u >= 0 && v >= 0 && 
        u < frame.mInstanceMap.cols && 
        v < frame.mInstanceMap.rows) {
        
        uchar id = frame.mInstanceMap.at<uchar>(v, u);
        if (id == 255) {  // 人体区域
            // 降低权重或直接跳过
            continue;
        }
    }
}
```

### 方案2：特征点质量评估

**思路**：评估每帧的特征点质量，质量低的帧不创建关键帧

```cpp
float Tracking::EvaluateFrameQuality(Frame &frame) {
    int goodFeatures = 0;
    
    for (int i = 0; i < frame.N; i++) {
        if (frame.mvpMapPoints[i] && !frame.mvbOutlier[i]) {
            // 检查是否在静态区域
            int u = cvRound(frame.mvKeysUn[i].pt.x);
            int v = cvRound(frame.mvKeysUn[i].pt.y);
            
            if (!frame.mInstanceMap.empty()) {
                uchar id = frame.mInstanceMap.at<uchar>(v, u);
                if (id == 0) {  // 静态背景
                    goodFeatures++;
                }
            } else {
                goodFeatures++;
            }
        }
    }
    
    // 返回好特征点的比例
    return (float)goodFeatures / frame.N;
}

// 使用
if (NeedNewKeyFrame()) {
    float quality = EvaluateFrameQuality(mCurrentFrame);
    if (quality > 0.3) {  // 至少30%的好特征点
        CreateNewKeyFrame();
    } else {
        std::cout << "[Tracking] Skip keyframe, quality too low: " 
                  << quality << std::endl;
    }
}
```

```cpp
// 在 Track() 函数中，创建关键帧之前
if (NeedNewKeyFrame()) {
    // 统计动态特征点比例
    int dynamicCount = 0;
    for (int i = 0; i < mCurrentFrame.N; i++) {
        if (mCurrentFrame.mvbDynamic[i]) {
            dynamicCount++;
        }
    }
    
    float dynamicRatio = (float)dynamicCount / mCurrentFrame.N;
    
    // 如果动态点超过50%，跳过关键帧
    if (dynamicRatio > 0.5) {
        std::cout << "[Tracking] Skip KF: too many dynamic points (" 
                  << (dynamicRatio * 100) << "%)" << std::endl;
    } else {
        CreateNewKeyFrame();
    }
}
```

## 📊 性能消融实验 (Ablation Study)

我们在 `fr3_walking_xyz` 数据集上进行了严格的消融对比（各运行 3 次取平均）：

| 实验设置 | 配置参数 | 平均 ATE (KeyFrames) RMSE (m) | 平均 RPE (Camera, 0.5m) RMSE (m) | RPE 提升幅度 |
| --- | --- | --- | --- | --- |
| **Baseline (仅语义剔除人)** | `Occl=0`, `Dyn=0` | 0.01784 | 0.02399 | - |
| **Exp A: 仅剔除动椅子** | `Occl=0`, `Dyn=1` | 0.01848 | 0.02264 | **📉 5.6%** |
| **Proposed (全功能)** | `Occl=1`, `Dyn=1` | **0.01741** | **0.02222** | **📉 7.4%** |

**深度分析（重要发现）**：
1.  **单纯剔除的风险 (Exp A vs Baseline)**：
    - 开启几何剔除后，**局部漂移 (RPE)** 确实降低了 (0.0240 -> 0.0226)，说明我们在局部做得更准了。
    - **但是**，**全局误差 (ATE)** 反而**略有上升** (0.0178 -> 0.0185)。这说明在严重遮挡下，单纯“做减法”（剔除特征点）会导致系统约束减少，虽然去掉了错点，但也让跟踪变得更脆弱，容易引起全局尺度的漂移。这解释了为什么仅靠剔除是不够的。

2.  **遮挡处理的关键作用 (Proposed vs Exp A)**：
    - 正因为“单纯剔除”带来了不稳定性，我们引入了 **遮挡处理**（智能跳过关键帧）。
    - 结果立竿见影：ATE 从 0.0185 骤降至 **0.0174**，不仅修复了剔除带来的负面影响，还超越了 Baseline。
    - **结论**：**“几何剔除”负责净化数据（修内功），“遮挡处理”负责规避风险（选时机）。两者缺一不可。**
